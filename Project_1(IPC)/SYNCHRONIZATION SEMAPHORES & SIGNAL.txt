SYNCHRONIZATION: SEMAPHORES & SIGNALS

1. WHY SYNCHRONIZATION IS NEEDED

Synchronization is needed when multiple processes access shared resources.

Without synchronization, processes may interfere with each other and produce incorrect results.

Example:
Two processes update the same variable at the same time. The final value may be incorrect.


2. CRITICAL SECTION

A critical section is the part of a program where a process accesses a shared resource.

Only one process should access a critical section at a time when mutual exclusion is required.


3. RACE CONDITION

A race condition occurs when multiple processes access shared data at the same time and the result depends on the order of execution.

Example:

    counter = 0

Two processes both execute:

    counter = counter + 1

The expected result is 2, but the result can become 1 because both processes may read the old value before updating it.


4. WHAT IS A SEMAPHORE?

A semaphore is a synchronization mechanism used to control access to shared resources.

Two main operations are:

    wait()   -> acquire the resource
    signal() -> release the resource


5. BINARY SEMAPHORE

A binary semaphore has only two values:

    0 -> unavailable
    1 -> available

It is commonly used for mutual exclusion.

Example:

    wait(S)
    Critical Section
    signal(S)


6. COUNTING SEMAPHORE

A counting semaphore can have values greater than 1.

It is used when multiple identical resources are available.

Example:

If there are 3 printers:

    S = 3

Three processes can use the printers. A fourth process must wait until one printer becomes free.


7. WHAT IS A SIGNAL?

A signal is a notification sent to a process to inform it that an event has occurred.

Signals are commonly used in Unix/Linux systems.


8. HOW SIGNALS WORK

A signal can be sent by the operating system or another process.

When a process receives a signal, it can handle it, ignore it if allowed, or perform the default action.


9. COMMON SIGNALS

SIGINT:
    Interrupts a process.
    Example: Ctrl + C.

SIGTERM:
    Requests a process to terminate gracefully.

SIGKILL:
    Forcefully terminates a process.
    Cannot be caught or ignored.


10. USES OF SIGNALS

Signals are used for:

    - Process termination
    - Process interruption
    - Process notification
    - Process management
    - Graceful shutdown


11. SEMAPHORE VS SIGNAL

Semaphore:
    Controls access to shared resources.
    Uses wait() and signal().
    Helps prevent race conditions.

Signal:
    Notifies a process about an event.
    Examples: SIGINT, SIGTERM, SIGKILL.
